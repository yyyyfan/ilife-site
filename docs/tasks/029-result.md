# 任务 029/030 结果：补齐缺失的图片

两个缺口一起做：公演缺封面 248 场、歌曲缺封面 18 首。

## 029 公演封面：248 → 179（补上 69 场）

### 思路

025 只收「出处 X 帖自己的图」——帖里没图就永远没封面。但 248 场里有 **153 场的出处是
eventernote 活动页**、13 场是 tiget 售票页，这些页面都带主办方的活动主视觉（海报/时间表），
正是 025 收不到的那一层。所以改从**出处页面的 `og:image`** 取。

### 扫出来的结果

| 阶段 | 数量 |
|---|---|
| 缺封面公演 | 248 |
| 拿到候选图（og:image 存在且不是站点 logo） | 184 |
| 下载后可用 | 79 |
| 人工复核剔除 | 10 |
| **最终补上** | **69 场** |

### 三道过滤，缺一不可

1. **域名白名单式跳过**：`x.com`（帖本身没图，og:image 只是视频封面）、`ja.wikipedia.org`、
   `ameblo.jp`/`lineblog.me`（og:image 是博客头图）、`livefans.jp`（403 需要登录）。
2. **样板图识别**（自动）：海报一定是彩色且不满屏单色的。
   LivePocket 的「不正なリクエスト」错误页（近乎纯黑）和 imaginate 的 logo（纯白零饱和）
   都是 `sat<0.06 && (white>0.5 || dark>0.5)` —— 这一条刷掉 **102 张**。
3. **人工复核**（10 张）：站点的 1200×630 分享卡、售票页登录墙截图、翻拍屏摄、
   被四场共用的主办方「9」logo、只有一个看不清 logo 的黑色窄条。

### 尺寸门槛的取舍

第一版要求宽度 ≥500px，挡掉 25 张 350–500px 的售票站小图。这些其实是真海报，
卡片展示宽度约 230px，够用；放宽到 **340px** 后多补了 22 场。
代价是灯箱里会偏模糊——比留一个 🎤 占位符好。

### 剩下的 179 场是什么

- **2022 年 61 场**：eventernote 上这些活动的主视觉就是坏的（LivePocket 图床返回错误页，
  主办方当年把错误页当图传上去了），页面上没有第二张可用的图。要补只能逐场找主办方 X 帖。
- **2027 年 11 场**：官方还没出海报，等。
- 其余分散在各年的小场次，出处页没有主视觉。

## 030 歌曲 jacket：18 → 2（补上 16 首）

18 首缺封面只对应 8 张 jacket（EP/单曲的收录曲共用封面）。沿用库里已有的约定：
`img/jacket-<JAN>.webp`、`category=official`、`text=『…』公式配信ジャケット`、`source=Apple Music`。

| 作品 | 覆盖歌曲 |
|---|---|
| みんなのあいす屋さん | 4 首（i / みんなのあいす屋さん / 愛キョウ！… / 私はかわいいよ絶対） |
| らぶりー属性 | 3 首 |
| はっぴ〜ばに〜ふぁんたじ〜 | 3 首 |
| 初恋サマーライン♡ | 2 首 |
| To be alive / スター☆まむナイズ / Snow Magic / MY HERO | 各 1 首 |

**仍缺 2 首**：`Ride On!`（未音源化，没有 jacket）、`PIXEL by PIXEL`（只发在 YouTube，
配信平台没有）。这两首的封面不该硬凑。

### 两个坑

1. **Apple 的作品名带后缀**：`みんなのあいす屋さん - EP`、`To be alive - Single`，
   直接比对作品名永远不命中。要剥掉 `- EP / - Single / - Album` 再比。
2. **`らぶりー属性` vs `らぶりー属性♡`**：Apple 的作品名比库里多一个 ♡。
   归一化时要去掉 `♡ ！ ! ？ ? ・ 、 , .` 这类标点。
3. 取文件名当 JAN 时**不能先替换尺寸**：`.../4582649617574.jpg/100x100bb.jpg` 的倒数第二段
   才是 JAN，先换成 `1200x1200bb` 会把文件名变成 `1200x1200bb`，8 张图会互相覆盖。
