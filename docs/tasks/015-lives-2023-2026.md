# 015 补全 2023–2026 年演出（严格出处）

执行者：Codex
分支：`codex/015-lives-2023-2026`（只推送这个分支，不推 main，不部署；见 AGENTS.md 分支流程）

## 背景
2020–2022 年已经补全，共 297 场。2023 年以后，库里只有主催的大型公演：2023 年 3 场，2024 年 3 场，2025 年 2 场，2026 年 12 场，明显缺了对バン、フェス、リリイベ、生誕祭等。2027 年的 11 场（JAPANLiFE! 2027）已经核对过，不在本单范围内。

## 目标
补全 2023-01-01～2026-12-31 的全部演出，包括官方已经公布的未来场次。每场都要有真实、可以打开、内容对得上的出处。按年份顺序做：2023 → 2024 → 2025 → 2026。

## 来源规则（与 012 相同）
1. 主出处优先级：@iLiFE_official 的出演告知、当日「本日の出演」、タイムテーブル帖 > 官网 https://ilife-heroines.com/ 的 schedule / topics > 主办方或会场官网的活动页。
2. Eventernote / LiveFans 只当线索。只有在打开页面、确认页面上的 iLiFE!、日期、会场都一致后才能用，并在 note 标 `仅非官方来源`。**不得拼接或猜测 events 编号或推文 ID**，只用实际搜到并打开过的 URL。
3. 推文出处必须是正文或图片里能看到这场演出的帖子。只讲特典或别的活动的帖子不算。
4. 月度排期图是唯一出处时，在 note 注明「来源为月度排期图」。
5. 会场容纳人数，只在能直接看到这个数字的具体页面上才填，并把该页写入 sources；地址同理。找不到就留空。
6. 日期一律用 JST（推文时间由 post ID 换算）。取消或延期的场次要保留并注明。查不到的字段留空。找不到任何真实出处的场次不要收录。
7. 标题以出处原文为准。新会场先查重，复用 venues 里已有的记录。
8. 现有的 2023–2026 年 20 场和 2020–2022 年的数据都不要改，只新增。如果发现已有的场次有错，写进结果，不要直接改。

## 配图（顺带，可选）
如果出演告知帖本身就是 @iLiFE_official 或主办方官方账号发的告知图，可以按 013 的做法关联封面：下载原图转成 webp，不裁剪，宽高写入数据库，写入 `image_lives` 和 `cover_image_id`。没有就留空，不要另外去找。

## 执行要求
- 所有网络请求都要设超时（`curl -m 20` / `timeout=20`），不要挂长时间的后台任务。
- **每完成一年就提交并推送一次分支**，提交信息写明年份和场数，方便分批验收。
- 每年完成后运行 `python3 db/export.py --rebuild-derived`、`python3 db/export.py --check`、`python3 db/check_sources.py --year <年份>`。
