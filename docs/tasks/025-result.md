# 025 每场公演收录出处帖的全部图片，封面按代表性重算

## 需求

用户要求：演出图片不要一张，要所有相关的图片；封面使用最能代表当前演出的图片。

## 现状（动手前）

- `lives` 872 场，607 场有封面；`image_lives` 616 行 / 607 场 → **598 场只有 1 张图**，9 场 2 张。
- 前端 `app.js` 本来就支持多图（详情页「相关图片 · N 张」画廊 + 灯箱），只是数据只有一张。
- 413 场的出处是 X 帖，但每帖只取了 1 张。

## 做法

1. **扫描出处帖的全部媒体**（`db/live_images_scan.py`，fxtwitter `api.fxtwitter.com/i/status/<id>`，响应缓存在 `db/.cache_x/`）：
   412 场成功、1 场失败；单帖多图的 104 场；每场图片数分布 0:14 / 1:294 / 2:76 / 3:21 / 4:7。
2. **判重**：库里图片键名是 `img/live-<live_id>-<媒体ID>.webp`，按媒体 ID 比对。
   537 张帖内照片中 469 张已入库，**实际缺 68 张，分布在 43 场**。
3. **下载转码**：`name=orig` → 长边 ≤2048、webp（quality 88，>1MB 递减）、单张 21.6 MB 合计。
4. **上传 R2**：用户跑 `npx wrangler login` 授权后，逐张 `wrangler r2 object put ... --remote`，
   68/68 成功（1 张因文件名以 `-` 结尾首轮失败，单独重传成功），`r2_images.py add` 记入清单（4116 个对象），
   抽样 10 张从 `img.ilifefan.dpdns.org` 核对 200/类型/字节/md5 全对。
5. **入库 + 挂接 + 补时期**：`live_images.py --apply-new` → `--link` → `--fix-eras`。
6. **封面重算**：`--covers`。

## 封面规则

按档位打分，**同档保持现有封面**（不按面积抢，否则会把海报换成更大的时间表）：

`演出照(100) > 官方图(60，且出自该场出处帖再 +10) > 打歌服(40) > 成员(30) > 其他(20)`

结果：18 场封面变动，其中 **17 场原本没有封面**（从无到有），只有 live 502 是同类演出照之间换了一张。

## 踩到的坑

- `image_lives.ord` 是 `NOT NULL` 且**没有默认值**，`INSERT OR IGNORE` 会把 68 条静默丢弃（不报错）。
  必须先算 `MAX(ord)+1`。
- 新图片必须写 `image_eras`，否则 `export.py --check` 报 68 项「image_eras 与日期不符」；
  时期按 `eras.start <= image.date` 取最后一个。
- `wrangler` 单张上传约 10 秒（npx 启动占大头），68 张约 11 分钟，串行即可。
