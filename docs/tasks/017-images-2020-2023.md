# 017 补 2020–2023 年演出配图（逐场找主办方官方原帖）

执行者：Antigravity
分支：`agy/017-images-2020-2023`（只推送这个分支，不推 main，不部署；见 AGENTS.md 分支流程）

## 背景
016 去掉 Eventernote 图之后，早期年份的封面覆盖率偏低：2020 年 24/45，2021 年 48/95，2022 年 61/157，2023 年 106/175。本单逐场补上没有封面的场次。

## 做法
对每一场没有 `cover_image_id` 的 2020–2023 年演出：
1. 先看这场演出现有的出处帖，以及它引用或转发的帖子里有没有官方图。
2. 再去主办方或会场的官方 X 账号找这场的告知图、时刻表或出演者发表图。主办方可以从活动名、售票页或 Eventernote 页面（只当线索）上找到。
3. 再看 @iLiFE_official 和成员本人的账号：当天的「本日の出演」、时刻表、演后感谢合照都可以，但帖子正文或图片里要能看出是这一场。
4. 也可以用官方月度日程表和 TicketDive 等主办方自己建的售票页。

## 规则（与 016 相同，必须遵守）
- 只用官方图：主办方或会场的官方账号或官网、@iLiFE_official、成员本人的账号、主办方自己建的售票页。不要用 Eventernote、粉丝或转载的图，也不要用非主办方的其他团体账号的图。
- 每张图都必须打开原帖或原页面，确认日期、会场一致，并确认 iLiFE! 在出演名单上，或者帖子明确写了这一场。多日活动要配当天的图。**不得拼接或猜测 URL 和推文 ID。**
- 图片下载原图后转成 webp，**不裁剪、不改比例**，长边不超过 2048px，单张不超过 1 MB。`images.date` 用演出日期。来源帖写进 sources 并关联到图片。写入 `image_lives` 和 `cover_image_id`。
- 数据只改 `db/ilife.sqlite`，然后导出。不要改已有的封面和数据。
- 找不到的场次留空，在结果里写明查过哪些地方。

## 顺序与提交
按 2023 → 2022 → 2021 → 2020 的顺序做，**每做完一年就提交并推送一次**，提交信息写明这一年配了几场、查了几场。

## 执行要求
- 所有网络请求必须设超时（`curl -m 20` / `timeout=20`），单个命令不超过 10 分钟。不要挂长时间的后台任务，不要写没有超时的抓取循环。
- 每年做完后运行 `python3 db/export.py --check`。

## 结果
写入 `docs/tasks/017-result.md`：每年新配几场、来源账号类型统计、没配到的场次清单及原因。全部完成后，把状态改为「待验收」并附各年的提交号。
